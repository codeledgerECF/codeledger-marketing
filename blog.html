CodeLedger v0.10.82: a release you can rely on

CodeLedger now installs cleanly, connects from wherever you open your editor, keeps your agent working when an integration is missing or slow, and reports only what the evidence supports.

CodeLedger v0.10.82 is out. It makes CodeLedger dependable for your AI coding agents: it installs cleanly, connects from wherever you open your editor, keeps your agent working when an integration is missing or slow, and reports only what the evidence supports.

Before shipping, we installed the release candidate the way a new user would: clean machines, a real AI coding agent, and no prior setup. We fixed the issues that evaluation found in everyday use.

What changes for you

  • Your agent connects from any folder. Claude Code, Cursor, Windsurf, Codex and VS Code now connect to CodeLedger wherever you open them in your repository, not only at its root. Opened outside a repository, CodeLedger says so in one line.
  • Setup failures don't stop your work. If an integration is missing, outdated or slow, CodeLedger shows a short repair hint and your agent carries on. Nothing blocks an edit unless you have chosen to enforce a rule.
  • Every team member gets the same version. A repository can keep a chosen CodeLedger version. Upgrades check the new version before switching, keep a rollback copy and refuse accidental downgrades.
  • One clear verdict on your change. The local checks separate new problems from existing debt, label missing evidence plainly, and agree on a small first edit.
  • Safer installs. CodeLedger detects a damaged install and tells you how to fix it. If an install could not finish, the first command tells you why.
  • Honest numbers. Reports show context size as size, never as a saving, and say plainly when a result cannot be measured.
  • A free place to start. Without a license, your agent is pointed to free activation from the terminal, not to a tool it cannot use.

Why it matters

A context tool earns its place only if you can stop thinking about it. Each fix above removes a moment where you had to interpret, repair or second-guess CodeLedger instead of finishing your task.

For teams, the payoff is consistency. When a repository pins a version, every developer and cloud session runs it and gets the same verdict on the same change. A failed upgrade keeps your previous version.

For anyone weighing CodeLedger's value, the reports now stay honest about their limits. Measured results are shown as measured, estimates as estimates, and gaps as gaps.

Get it

  1. Install or update: npm install -g @codeledger/cli
  2. In each repository, run codeledger upgrade and commit the files it lists, so cloud sessions get the same version.
  3. Starting fresh? Run codeledger ready in your repository.

v0.10.82

v0.10.82 · 2026-10-29

A reliable runtime, clearer evidence, and one verdict

Keep agents working through setup failures, choose a stable repository version, and see what current evidence actually supports.

What we heard

A team using CodeLedger in cloud coding sessions found that a failed upgrade left their agent unable to work or repair its setup. We also heard that conflicting status messages and optimistic value claims made it difficult to tell whether a session was ready to continue.

These problems have the same practical cost: time spent interpreting or repairing the tool instead of completing the task.

Before release, an independent evaluation installed the release candidate the way a new user would, in clean environments and with a real coding agent. It found more friction:

  • MCP connections failed when the client was opened in a subfolder.
  • Different checks gave different verdicts on the same one-line change.
  • A damaged download could go unnoticed.
  • Some repair messages pointed at an older version.
  • Users without a license were sent to a tool they could not use.

What we did

  • Keep agents working through setup failures. Missing, outdated, broken or slow integrations report a short repair hint and let work continue. Nothing blocks your work unless you have chosen to enforce a rule. Repair commands stay available.
  • Make the repository version predictable. Repositories can keep a chosen CodeLedger version. Upgrades prepare and validate the replacement before switching, retain a rollback copy, and refuse accidental downgrades. Routine commands leave the committed runtime alone. Repairing a broken install keeps your session history.
  • Use consistent MCP setup. Supported client configurations launch the repository's chosen runtime. Setup also works on minimal Linux images. Windsurf users get a configuration they can import.
  • Give local checks one verdict. Verification, task review and pre-PR checks distinguish new blocking problems from inherited debt. Problems introduced or worsened by the current work can block; existing debt stays visible without being presented as a new failure. Missing evidence is labeled, and a stricter mode remains available.
  • Explain whether context can be trusted. Reports identify moved revisions, a different branch or worktree, an outdated base, mismatched tasks and older evidence, with a suggested repair. Recall reports distinguish missing evidence from measured results, and refreshing context preserves the session's work history.
  • Connect MCP clients from any folder in the repository. Client configurations now work wherever the client is opened. A client opened in a subfolder connects. A client opened outside a repository gets a one-line explanation instead of an error dump. Stopping the client also stops the server.
  • Agree on a first local change. A small first edit on a new repository's main branch is no longer flagged as too large, and the quicker local checks say when the pre-PR check can be stricter.
  • Never run an unverified download. The installed command now confirms its files are intact before running, and repairs or refuses a damaged copy.
  • Make install problems visible. If installation could not fetch the binary, the first command explains why. Repair advice reinstalls the exact version you chose and says plainly when a version's files are not yet available. Damaged repository settings now produce a message that names the file and how to restore it.
  • A clear free starting point. Without a license, the MCP connection now points to activation from your terminal, which is free, instead of a licensed tool.
  • Describe value honestly. Descriptive bundle sizes and measured outcomes stay distinct. Estimates remain estimates, and a small bundle is not presented as proof of a percentage saved across the whole repository.

What this release does for you

CodeLedger becomes easier to keep stable across local and cloud sessions, and its reports make the evidence and remaining limitations easier to assess. After installing v0.10.82, run codeledger upgrade in each repository and commit the exact files it lists so cloud sessions receive the same runtime.

Some enforcement limits are documented in the user guide. A configuration file is not evidence that a client has imported it, and missing activation or measurement evidence is not a successful check. We will keep these distinctions visible as the product develops.
